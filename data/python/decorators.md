In Python, a decorator is a higher-order function and structural design pattern that dynamically extends, modifies, or enhances the behavior of an existing function, method, or class without explicitly altering its internal source code. This capability relies fundamentally on Python's execution model, which treats functions as first-class citizens capable of being assigned to variables, passed as arguments to other functions, and returned from functions as return values. At a mechanical level, decorators depend on nested function definitions and lexical closures: a decorator function accepts the original target function as an input parameter, declares an inner wrapper function that encapsulates pre-processing and post-processing execution logic surrounding the original function call, and ultimately returns this new wrapper object. Python provides the `@decorator_name` syntactic sugar placed directly above a target function declaration, which acts as a clean, declarative alias for the underlying evaluation assignment `target_function = decorator_name(target_function)`.

To ensure decorated functions can accommodate arbitrary input signatures, the inner wrapper function is conventionally parameterised using variable positional and keyword unpacking (`*args`, `**kwargs`), which forwards arguments cleanly to the encapsulated callable. Because decorating a function effectively replaces the original function object with the wrapper object in the module scope, metadata such as the original function's name (`__name__`), docstring (`__doc__`), and type annotations are masked by default; to preserve this introspection metadata, standard engineering practice dictates annotating the wrapper with `@functools.wraps(func)`. Beyond single-tier functional wrappers, decorators can also accept custom configuration parameters at runtime through decorator factories—a three-tiered function structure where an outermost function accepts the configuration arguments, returns the actual decorator function, which then returns the final executable wrapper. Alternatively, stateful decorators can be constructed using class objects by implementing the `__call__` special method to make class instances callable as wrapper objects. Industrially, Python decorators serve as a cornerstone of clean, modular code architecture, widely applied in cross-cutting concerns such as logging execution metrics, enforcing route authentication and role-based access control in frameworks like FastAPI and Flask, implementing memoization and response caching via `functools.lru_cache`, enforcing rate limiting, validating input parameters, and managing database session state or transaction rollbacks.
